## 🔐 Phase 1 — Auth & Routing Foundation

### 1.1 Middleware — Route Protection

```
src/middleware.ts
```

- [ ] Read JWT from cookie or `Authorization` header
- [ ] If no valid token → redirect to `/login`
- [ ] If token valid → decode role claim
- [ ] Enforce role-based route access:
  - `/radiologist/**` → only `Lab_Technician` or `Radiologist` role
  - `/doctor/**` → only `Doctor` role
  - `/admin/**` → only `Admin` role
- [ ] On role mismatch → redirect to their correct dashboard
- [ ] Handle token expiry → redirect to `/login` with `?expired=true`

### 1.4 Token Management — `lib/auth.ts`

- [ ] Store access token in memory (not localStorage)
- [ ] Store refresh token in HTTP-only cookie (handled by backend, just don't touch it client-side)
- [ ] `getAccessToken()` — returns current token or null
- [ ] `refreshAccessToken()` — calls refresh endpoint, updates in-memory token
- [ ] `clearTokens()` — clears memory token (for logout)
- [ ] Auto-refresh access token 60s before expiry using a background interval
- [ ] On refresh failure → call logout flow → redirect to `/login`

---

### 1.5 API Client — `lib/api.ts`

- [ ] Axios (or fetch wrapper) base instance with `baseURL` from env
- [ ] Request interceptor: attach `Authorization: Bearer <token>` header
- [ ] Response interceptor:
  - On `401` → attempt token refresh → retry original request once
  - On second `401` → logout + redirect
  - On `403` → show "Access Denied" toast
  - On `500` → show generic "Something went wrong" toast
- [ ] All endpoints typed with TypeScript interfaces

## 🔒 Phase 7 — Security & Data Handling

- [ ] **No credentials, diagnosis text, or patient notes stored in localStorage or sessionStorage**
- [ ] All API calls over HTTPS (enforced by backend, but never hardcode `http://` in frontend)
- [ ] JWT access token stored only in memory (JavaScript variable / Zustand store)
- [ ] Refresh token: HTTP-only cookie (do not try to read it client-side)
- [ ] Sensitive form fields (password, OTP): `autocomplete="off"` where appropriate
- [ ] CSRF protection: include CSRF token header on mutating requests if backend requires it
- [ ] Pre-signed URLs for image/PDF downloads must expire in 15 min — do not cache URLs

- [ ] **Language attribute** set on `<html lang="en">` (or `"am"` for Amharic)

## 📡 Phase 9 — State Management

### Recommended: Zustand + React Query (TanStack Query)

- [ ] **Zustand store** for:
  - Current user (decoded from JWT): `{ user_id, name, role, email, hospital_id }`
  - Current language preference
  - Current annotation editing state (for image viewer)

- [ ] **React Query** for all server state:
  - `useCases(filters)` — cases list with caching + background refresh
  - `useCase(caseId)` — individual case with predictions
  - `usePatient(patientId)` — patient + case history
  - `useInferenceResult(caseId)` — AI predictions
  - `useAuditLogs(filters)` — admin logs
  - `useUsers()` — admin user list
  - Mutation hooks for: `useSubmitDiagnosis`, `useUploadImage`, `useSaveAnnotations`, etc.

## 🧪 Phase 10 — Error States & Edge Cases

Every page must handle:

- [ ] **Loading state** — skeleton loaders or spinners (not blank white screens)
- [ ] **Error state** — "Something went wrong" with a retry button
- [ ] **Empty state** — friendly message + illustration/icon (not just blank)
- [ ] **Network offline** — banner: "You appear to be offline. Changes may not save."
- [ ] **Session expired** — intercept 401 → redirect to login with `?expired=true` → show "Your session expired. Please log in again."
- [ ] **403 Forbidden** — "You don't have permission to view this" page
- [ ] **404 Not Found** — for invalid case IDs / patient IDs in URLs
- [ ] **AI inference timeout** — "Analysis is taking longer than expected" state on upload page
- [ ] **PDF generation timeout** (>18s) — "Report is still generating. Check back shortly."
